# Разработка FonemaGo

## Границы MVP

Один Python-процесс, Telegram Bot API через long polling, SQLite и локальные эталоны.
Русский интерфейс, испанский Испании и стандартный итальянский, по шесть карточек.
Нет веб-сервера, ИИ, платежей, истории занятий, Redis, внешней БД и админки.

## Окружение

```bash
uv sync --frozen
uv run pytest -q
uv run ruff check .
uv run fonemago doctor
```

Python 3.12–3.14. Рабочие пути в `.env` относительны текущему каталогу: запускайте
CLI из корня. `scripts/run.sh` делает это сам. Для обычного запуска без dev-пакетов
можно использовать `uv sync --frozen --no-dev`.

FFmpeg/FFprobe требуются только для `prepare`, не для unit-тестов или polling.
Тесты не требуют токена, сети и загрузки реального пользовательского аудио.
Зависимости фиксируются в `uv.lock`; после осознанного изменения `pyproject.toml`
обновите lock через `uv lock`, выполните тесты и проверьте запуск.

## Структура

```text
src/fonemago/
  config.py     .env / переменные окружения; токен SecretStr
  content.py    строгая схема контента, связи и контрольные суммы
  wiki.py       сбор кандидатов, языковые границы, лицензии Commons
  audio.py      загрузка оригиналов и подготовка эталонов FFmpeg
  db.py         SQLite, импорт, состояния, кеш file_id, backup API
  bot.py        команды, клавиатуры, карточки, голосовые и обработка ошибок
  cli.py        команды владельца, блокировка экземпляра, безопасные логи
content/
  catalog.json           опубликованный стартовый набор
  catalog-evidence.json  источники авторства/лицензий и ревизии Commons
data/                    локальные данные, игнорируются VCS
  fonemago.sqlite3
  audio/originals/
  audio/prepared/
  audio/manifest.json
scripts/
  run.sh                 запуск из установленного .venv
  build_demo_catalog.py  воспроизводимый сбор именно стартовой подборки
tests/                   офлайн-тесты с подменённой Telegram-сессией
docs/                    инструкции владельцу и разработчику
```

PDF — входные материалы, не файлы приложения. Описание отличий от исходного ТЗ:
нет скачивания голоса/FFprobe для пользователя, нет категорий в малом каталоге,
нет usernames/имён в БД, есть сбор кандидатов, атрибуция и проверка контента.

## Потоки

**Навигация:** `/start` → язык → страница каталога → карточка → два эталона.
Список разбит по 8 карточек; он уже пригоден для увеличения набора. «Следующий»
идёт по порядку внутри языка и циклически возвращается к первому звуку.

**Голос:** `rec:<card_id>` → проверка текущей карточки → ожидание voice → проверка
`duration` / `file_size` из Telegram → образец **слова** → `sendVoice(file_id)`.
Вызовов getFile и скачивания пользовательского аудио нет. Метаданные доверяются
Telegram: бот не декодирует/анализирует голос и не заявляет независимой проверки длительности.
Отсутствующий размер отклоняется. Допустимые границы: 15 секунд и 1 048 576 байт включительно.

Ожидание записи сохраняется для повторных попыток, пока пользователь не сменит карточку,
язык, не вызовет `/cancel`, `/forget` или пока процесс не перезапустится. При старте
ожидания сбрасываются. Старый `rec` от другой карточки отклоняется, чтобы не сопоставить
голос не с тем словом. Старые ссылки на существующие карточки остаются рабочими.

**Контент:** wiki → кандидаты → проверка → JSON + закреплённые SHA-256 → prepare →
validate → транзакционный импорт. Runtime читает только БД/диск и Telegram.

## База и расширение

Схема №1 создаётся при открытии. Таблицы:

- `languages`: стабильный код, описание JSON;
- `assets`: стабильный ID, метаданные JSON, SHA-256 подготовленного файла;
- `cards`: стабильный ID, внешние ключи языка и двух аудио, порядок, active, JSON;
- `sessions`: Telegram ID, язык, карточка, флаг ожидания;
- `telegram_files`: asset ID + bot ID + checksum → кеш file_id эталона;
- `schema_version`: версия схемы.

JSON не отменяет проверку: вход проходит строгие Pydantic-модели, связи проверяются
до импорта, в SQLite включены FK. WAL и `busy_timeout` предназначены для одного
основного процесса и безопасного резервного копирования, не для горизонтального масштабирования.

Импорт делает upsert, не удаляет пользовательские состояния, деактивирует отсутствующие
и черновые карточки. При ошибке — rollback. Обновление байтов эталона меняет checksum,
старый Telegram-кеш перестаёт подходить. file_id сохраняется отдельно для каждого бота.
Если Telegram отвергает кешированный ID, выполняется повторная загрузка локального файла.

Для полноценного каталога добавляйте карточки и ассеты с новыми стабильными ID;
не переиспользуйте старый ID для другого звука. Категории и несколько примеров можно
добавить следующей версией схемы. Текущая схема уже не ограничена шестью записями,
но намеренно содержит один пример на карточку. Для новых языков потребуется также
расширить Literal-модели и проверку сборщика. Автоматических миграций в PostgreSQL нет.

Изменение структуры БД требует явной новой версии и миграции; неизвестная версия
отклоняется. Перед этим обязательны backup и тест восстановления.

## Команды

| Команда | Назначение |
|---|---|
| `fonemago run` | Запустить polling, проверить runtime-аудио, сбросить ожидания записи |
| `fonemago prepare` | Скачать/проверить оригиналы и создать MP3 |
| `fonemago validate` | Проверить схему и подготовленные файлы |
| `fonemago import-content` | Загрузить опубликованные карточки в БД |
| `fonemago doctor` | Показать локальную готовность, без сетевых запросов |
| `fonemago backup PATH` | Согласованная новая копия SQLite |
| `fonemago collect-ipa Spanish` | Извлечь кандидатов из таблицы IPA |
| `fonemago collect-word Italian figlio` | Найти транскрипции и аудиокандидаты слова |
| `fonemago collect-file 'Palatal_nasal.ogg'` | Получить метаданные файла; при недостатке данных потребовать ручную проверку |

Общий сборщик не пытается угадывать автора в старом шаблоне Commons или разрешать
все виды лицензий. Для некоторых файлов стартовой подборки автор подтверждён вручную
в build-скрипте; это не универсальное правило для любых новых файлов.

## Конфигурация

| Переменная | По умолчанию |
|---|---|
| `BOT_TOKEN` | Пусто; обязателен только для run |
| `DB_PATH` | `data/fonemago.sqlite3` |
| `AUDIO_DIR` | `data/audio` |
| `CONTENT_PATH` | `content/catalog.json` |
| `MAX_VOICE_SEC` | `15` |
| `MAX_VOICE_BYTES` | `1048576` |
| `LOG_LEVEL` | `INFO` |

`ADMIN_IDS`, `TEMP_DIR`, webhook-порт и S3-ключи не нужны. При изменении лимитов
не забудьте обновить короткое пользовательское описание.

## Безопасность и обработка ошибок

- Только личные чаты. Обработчики групп молча игнорируются.
- Параметризованные SQL-запросы; ID ассетов ограничены безопасным форматом.
- Скачивания только с HTTPS Wikimedia-доменов; каждый redirect проверяется до перехода.
  Ответ ограничен 20 МиБ, таймаут — 30 секунд, только краткие повторы временных ошибок.
- Сбор запускает владелец локально, не пользователь бота. HTML — внешний недоверенный ввод.
- FFmpeg получает только локальный файл, без shell; протоколы ограничены file/pipe,
  обработка ограничена временем. Системный FFmpeg нужно своевременно обновлять.
- Процесс запускается без root. CLI использует umask 077; `.env` защищайте отдельно.
- Один процесс run/prepare/import на DB_PATH, flock освобождается ОС после завершения.
  **Lock-файл не удаляется для снятия блокировки:** удаление может позволить два экземпляра.
- Полные updates, имена, тексты и голосовые не пишутся в БД/логи. Сообщения об ошибках
  логируют класс исключения без traceback и входных данных. Токены маскируются.
- Есть ограничение частоты действий пользователя, ограниченное число обработчиков
  и последовательная работа с состоянием пользователя. Это базовая защита демо,
  а не защита от распределённой атаки.
- При 429 учитывается retry_after (до 30 с, до двух повторов). При сетевой ошибке
  отправки нет слепых повторов: они могли бы продублировать сообщение.
- После 403 не пытаемся отправить пользователю сообщение об ошибке.
- Несколько сообщений одного упражнения могут быть доставлены частично при обрыве сети.
  Транзакции между Telegram и SQLite, гарантии exactly-once и постоянной очереди задач нет.

## Проверка перед выпуском

Автотесты покрывают схему/пути/ссылки, языковые границы HTML, лицензии без подмены
footer-лицензией, импорт/rollback, скрытие черновиков, кеш, backup, lock, навигацию,
голосовые, лимиты, устаревшие callback, минимизацию данных и маскирование секретов.

С токеном обязательно вручную пройти [чек-лист Linux-гайда](run-linux.md#8-короткий-чек-лист-перед-демо).
Тестовая Telegram-сессия не проверяет реальный интерфейс клиента, действительность
токена, доступность Bot API и слуховое соответствие аудио транскрипции.
Нагрузочные гарантии «1000 пользователей» исходного ТЗ не подтверждены.
