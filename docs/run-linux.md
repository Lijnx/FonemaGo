# Запуск FonemaGo под Linux

Гайд рассчитан на обычный Linux и Linux-окружения вроде WSL. Команды выполняются
**в Linux-терминале**, не в Python и не от root. Специальных действий в Windows здесь нет.

## Что нужно знать заранее

- Бот работает через **long polling**: сам подключается к Telegram по HTTPS.
- Пользователям нужен только Telegram и ссылка `https://t.me/USERNAME_БОТА`.
- Белый IP, проброс портов, домен, сертификат, VPN-туннель и входящие порты не нужны.
- Интернет должен разрешать исходящие подключения к `api.telegram.org:443`.
- Для первой установки нужны также Python-пакеты и Wikimedia. В обычной работе
  Wikipedia/Wiktionary не используются: контент уже находится на диске.
- При выключенном компьютере, спящем хосте или остановленном Linux-окружении бот
  недоступен. systemd или tmux не сохранят его работу при выключении ноутбука.
- После остановки Telegram сохраняет ещё не полученные обновления не более 24 часов.
  Обновления, уже принятые процессом перед аварией, не гарантированно восстановятся.
- Для одного токена запускайте **один экземпляр**. Один и тот же каталог данных защищён
  файловой блокировкой, но другой компьютер или другой `DB_PATH` она не защитит.

## 1. Первая установка

### 1.1. Системные зависимости

Нужны Python 3.12–3.14, `uv`, FFmpeg (включая FFprobe). Для фонового режима без
systemd можно дополнительно установить tmux.

Ubuntu / Debian:

```bash
sudo apt update
sudo apt install python3 python3-venv ffmpeg curl ca-certificates tmux
```

Если версия системного Python ниже 3.12, `uv` сможет установить подходящий Python отдельно.
FFmpeg нужен только для подготовки/изменения эталонного контента, не для голосовых.

Установите `uv` по [официальной инструкции](https://docs.astral.sh/uv/getting-started/installation/).
Вариант без запуска скрипта непосредственно из сети:

```bash
curl -LsSf https://astral.sh/uv/install.sh -o /tmp/uv-install.sh
less /tmp/uv-install.sh
sh /tmp/uv-install.sh
```

Откройте новый Linux-терминал, затем проверьте:

```bash
uv --version
ffmpeg -version
ffprobe -version
```

### 1.2. Папка проекта и Python-окружение

Пример пути в этой среде — `/home/lynx2/FonemaGo`. На другом компьютере замените путь.
Проект лучше хранить на Linux-файловой системе, в домашнем каталоге пользователя,
а не на сетевом диске. Не запускайте два экземпляра с общей SQLite.

```bash
cd /home/lynx2/FonemaGo
uv sync --frozen --python 3.12
chmod +x scripts/run.sh
```

`--frozen` использует зафиксированные зависимости `uv.lock`. Активация `.venv`
командой `source` не нужна. Нативно проект также проверен на Python 3.14.

### 1.3. Создание Telegram-бота и секрет

1. Найдите официальный `@BotFather` в Telegram.
2. Отправьте `/newbot`, выберите имя и свободный username.
3. Скопируйте выданный токен **только в локальный `.env`**.
4. При желании задайте описание и команды через BotFather.

Создайте конфигурацию один раз; **не перезаписывайте уже существующий `.env`**:

```bash
cp -n .env.example .env
chmod 600 .env
nano .env
```

Укажите `BOT_TOKEN=...` без угловых скобок. Остальные значения можно оставить
как есть. Не публикуйте `.env`, не присылайте токен в чат и не вводите его в команду,
которая сохранится в истории shell. Если токен раскрыт — перевыпустите его в BotFather.

Переменные окружения имеют приоритет над `.env`. Если вы когда-то делали
`export BOT_TOKEN=...`, старое значение может перекрывать файл. Удалить его из
текущей оболочки: `unset BOT_TOKEN`.

### 1.4. Подготовка каталога

```bash
uv run --frozen fonemago prepare
uv run --frozen fonemago validate
uv run --frozen fonemago import-content
uv run --frozen fonemago doctor
```

Что происходит:

- `prepare` загружает утверждённые файлы Wikimedia, проверяет SHA-256 оригиналов,
  преобразует аудио в MP3 и создаёт `data/audio/manifest.json`.
- Уже подготовленные и неизменённые файлы повторно не конвертируются.
- Если оригинал на Wikimedia изменился, операция остановится: сначала нужна проверка,
  а не автоматическое принятие новых байтов.
- `validate` проверяет комплектность и контрольные суммы подготовленного набора.
- `import-content` транзакционно загружает опубликованные карточки в SQLite.
- `doctor` показывает локальное наличие зависимостей, файлов и конфигурации, но
  **не проверяет действительность токена и доступность сети**.

Для стартового набора ожидается `12 cards, 22 prepared audio assets`, импорт:
`{"es": 6, "it": 6}`. Файлы в `data/` локальные, в репозиторий не включаются.

**В текущей рабочей папке аудио уже подготовлено и база импортирована.** Если вы
не переносили проект и не удаляли `data/`, заново выполнять `prepare` не требуется.
В этой среде системный FFmpeg отсутствовал: подготовка выполнена временным
инструментом, без установки системных пакетов. Для будущего обновления контента
установите FFmpeg по инструкции выше.

### 1.5. Первый запуск

```bash
./scripts/run.sh
```

Скрипт переходит в каталог проекта и запускает уже установленный Python напрямую:
при каждом старте не скачиваются зависимости. Этот режим занимает терминал.
Для остановки нажмите **Ctrl+C** и дождитесь завершения процесса.

Запуск автоматически снимает старый webhook, **не запрашивая очистку очереди**.
Поэтому не используйте тот же токен одновременно с другим сервисом.

В Telegram откройте своего бота и пройдите сценарий из README. Для проверки внешнего
доступа откройте его с телефона через мобильный интернет — домашний адрес не нужен.

## 2. Как запускать после каждого включения ноутбука

### Простой вариант — всегда доступен

1. Включите компьютер и интернет.
2. Откройте Linux-терминал. Если это WSL — само Linux-окружение должно быть запущено.
3. Выполните:

```bash
cd /home/lynx2/FonemaGo
./scripts/run.sh
```

4. Не закрывайте терминал; проверьте `/start` в Telegram.

**Повторять установку, `uv sync`, создание `.env`, скачивание аудио и импорт базы
после обычной перезагрузки не нужно.** Всё хранится на диске.
Кнопка «Повторить слово» после перезапуска нажимается заново: ожидание старой
записи сбрасывается, язык и выбранная карточка сохраняются.

## 3. Фоновая работа через systemd — если он доступен

Проверьте:

```bash
systemctl --user status
```

Если команда сообщает, что systemd или пользовательская шина недоступны, переходите
к разделу tmux. **Не обязательно менять настройки хоста ради MVP.**

### Однократная настройка пользовательской службы

Сначала остановите бот в терминале через Ctrl+C.

```bash
mkdir -p ~/.config/systemd/user
cp docs/fonemago.service.example ~/.config/systemd/user/fonemago.service
nano ~/.config/systemd/user/fonemago.service
```

В двух строках `WorkingDirectory` и `ExecStart` замените `/home/YOUR_USER/FonemaGo`
на абсолютный путь к вашему проекту. Служба запускается от текущего пользователя,
`sudo systemctl` для неё не используется. Если путь содержит пробелы, корректно
экранируйте его согласно синтаксису systemd; проще выбрать путь без пробелов.

```bash
systemctl --user daemon-reload
systemctl --user enable --now fonemago
systemctl --user status fonemago --no-pager
```

Результат должен содержать `active (running)`. При аварийном завершении systemd
попытается перезапустить процесс. После 10 быстрых неудач служба остановится,
чтобы не перезапускать бесконечно неверную конфигурацию.

### Обычное управление

```bash
systemctl --user stop fonemago
systemctl --user start fonemago
systemctl --user restart fonemago
systemctl --user status fonemago --no-pager
journalctl --user -u fonemago -n 100 --no-pager
journalctl --user -u fonemago -f
```

Команды независимые: не нужно выполнять все подряд. `journalctl -f` — просмотр
новых логов; Ctrl+C прекращает просмотр, а не работу службы.

После исправления частых ошибок старта:

```bash
systemctl --user reset-failed fonemago
systemctl --user start fonemago
```

### После перезагрузки

Откройте Linux-окружение и проверьте:

```bash
systemctl --user start fonemago
systemctl --user status fonemago --no-pager
```

`start` безопасен, если служба уже работает. Не запускайте дополнительно `run.sh`.
В обычном Linux включённая пользовательская служба стартует при запуске
пользовательского менеджера. В WSL и похожих окружениях это **не обещание запуска
самой Linux-системы после перезагрузки хоста**. Пока Linux не запущен, служба не работает.
Автозапуск до входа пользователя требует отдельной настройки менеджера сеансов
(например, linger) и здесь не является обязательным сценарием.

Логи хранятся в системном журнале с его политикой ротации, а не в бесконечно
растущем файле проекта. Проверить объём: `journalctl --user --disk-usage`.
Настройку лимитов журнала согласуйте с администратором ОС; не очищайте общий журнал
ради одного бота. Логи приложения не содержат записей голоса и полных Telegram updates.

## 4. Фоновая работа без systemd: tmux

Из каталога проекта:

```bash
tmux new-session -s fonemago ./scripts/run.sh
```

- Отсоединиться, не останавливая бот: **Ctrl+B**, отпустить, затем **D**.
- Проверить существующие сессии: `tmux ls`.
- Вернуться: `tmux attach-session -t fonemago`.
- Остановить бот: внутри сессии **Ctrl+C**.

Не создавайте вторую сессию для того же токена. tmux переживает закрытие терминала,
но не перезагрузку, выключение, остановку окружения или аварию процесса. После
включения запустите указанную команду заново. Это не замена systemd с автоперезапуском.

## 5. Резервные копии

SQLite работает в WAL-режиме. **Не копируйте только живой `.sqlite3` обычным `cp`:**
часть последних изменений может быть в WAL. Встроенная команда использует
SQLite backup API и может работать одновременно с ботом.

```bash
uv run --frozen fonemago backup data/backups/fonemago-2026-10-19.sqlite3
```

Подставьте актуальную дату/время. Существующий файл копии не перезаписывается.
Папку резервных копий лучше регулярно переносить на другой диск: копия на том же
ноутбуке не защищает от поломки его накопителя.

Копируйте также:

- `content/` — утверждённый каталог, источники и лицензии;
- `data/audio/` — оригиналы, подготовленные MP3 и manifest;
- исходный код и `uv.lock`;
- `.env` — отдельно и только в защищённое/зашифрованное место.

Аудио статично во время обычной работы. При совместном бэкапе перед изменением
контента сначала остановите бот и не запускайте импорт/подготовку до окончания копии.
Рабочая БД и её копии содержат Telegram ID и текущий выбор. Ограничивайте доступ,
не выкладывайте их публично. Установите срок удаления старых копий, например 7 дней.
`/forget` не удаляет информацию из ранее сделанных резервных копий.

### Восстановление

1. Остановите все процессы бота. Убедитесь, что служба/сессия действительно завершилась.
2. **Переместите** текущую SQLite, а также её `-wal` и `-shm`, если они существуют,
   в отдельную папку. Не оставляйте старый WAL рядом с восстановленной БД.
3. Положите копию в путь `DB_PATH` (`data/fonemago.sqlite3` по умолчанию).
4. Восстановите согласованные `content/`, `data/audio/` и версию кода.
5. Проверьте права доступа и `.env`, затем выполните `validate` и запустите бот.
6. Проверьте карточки и отправку голоса. Состояние ожидания записи сбрасывается на старте.

После восстановления старой копии могут вернуться ранее удалённые пользовательские
состояния. Учитывайте это при обработке запросов на удаление. Если состояние пользователей
не нужно сохранять, каталог можно восстановить из контента новым импортом в новую БД.

## 6. Обновление и откат

1. Остановите процесс.
2. Сделайте backup БД, копию исходников, контента и аудио.
3. Установите новую версию исходников, **сохранив `.env` и `data/`**.
4. Выполните `uv sync --frozen`.
5. Если контент изменился: `prepare`, `validate`, затем `import-content`.
6. Запустите бот, проверьте `/start` и одну карточку каждого языка.

Импорт не дублирует записи с теми же ID. Удалённые из каталога и черновые карточки
становятся неактивными. Ошибка импорта откатывает транзакцию; проверка файлов выполняется
до изменения базы. Подготовка и импорт заблокированы, пока работает бот с тем же DB_PATH.

Для отката остановите процесс и восстановите **согласованный комплект** кода, БД и аудио
по предыдущему разделу. Не откатывайте только код, если новая версия меняла формат БД.
Текущая версия использует схему №1; универсального автоматического downgrade нет.

## 7. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Бот не отвечает | Компьютер включён, не спит, Linux запущен, процесс работает, интернет доступен |
| `Set BOT_TOKEN` | `.env` находится в корне проекта и содержит непустой токен |
| `TelegramUnauthorizedError` | Токен верен и не отозван; замените в `.env` и перезапустите |
| `TelegramConflictError` / конфликт updates | Другой процесс с тем же токеном, другой терминал/компьютер |
| `Another bot/import/preparation process` | Уже есть процесс с тем же DB_PATH; остановите его, не удаляйте lock-файл |
| `Database missing` / `Catalog is empty` | Выполнены ли prepare и import-content; правильный ли DB_PATH |
| `Missing or modified reference audio` | Выполните validate; восстановите аудио или подготовьте и импортируйте заново |
| `FileNotFoundError` при validate | Обычно нет manifest/аудио; сначала prepare |
| `HTTPError` при сборе/prepare | Источник временно недоступен, ограничил доступ или переместил файл; не обходите запрет частыми запросами |
| `Source changed` | Контрольная сумма оригинала изменилась; нужна повторная проверка источника |
| `Install ffmpeg` | Установите системный пакет ffmpeg; нужны оба ffmpeg и ffprobe |
| `TelegramNetworkError` / `TimeoutError` | DNS, исходящий HTTPS, сеть и доступность Telegram; пользователь может повторить действие |
| `TelegramForbiddenError` | Пользователь заблокировал бот; повторная отправка ему не поможет |
| Голосовое не принято после перезапуска | Откройте карточку и снова нажмите «Повторить слово» |
| `PermissionError` | Проект/data доступны текущему Linux-пользователю, .venv и run.sh доступны для запуска |
| systemd недоступен | Используйте обычный запуск или tmux |

Проверка сети **без токена**:

```bash
curl -I --connect-timeout 10 https://api.telegram.org
```

HTTP-ответ (даже редирект/ошибка страницы) подтверждает соединение, не валидность токена.
При обрыве сети polling повторяет соединение. Автоматическая доставка каждого ответа
после сетевой ошибки не гарантируется: это не очередь заданий с гарантией exactly-once.

Не прикладывайте `.env`, токены, БД пользователей и полные сообщения к публичным отчётам
об ошибках. Для диагностики достаточно типа ошибки и вывода `doctor` без секретов.

## 8. Короткий чек-лист перед демо

- [ ] `.env` заполнен и не опубликован.
- [ ] `validate` проходит; в базе по шесть карточек каждого языка.
- [ ] Запущен только один экземпляр.
- [ ] На телефоне через мобильный интернет доступны оба языка и оба аудио карточки.
- [ ] После записи слова приходят образец слова и ваше голосовое.
- [ ] Запись длиннее 15 секунд отклоняется.
- [ ] После Ctrl+C и повторного запуска бот снова отвечает.
- [ ] Резервная копия создана и хотя бы раз проверена восстановлением.
- [ ] Ноутбук не уходит в сон во время демо; Linux-окружение не останавливается.
